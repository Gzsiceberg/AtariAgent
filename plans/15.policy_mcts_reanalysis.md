# Policy MCTS Reanalysis

## Goal

Refresh policy targets for **99% of sampled replay items** using MCTS and the
delayed target network. Keep stored self-play policy targets for the remaining
1%. Value reanalysis continues independently for every valid bootstrap.

## Configuration

Add under `training`:

```yaml
policy_reanalysis_ratio: 0.99  # 0 disables policy reanalysis
```

Validate the ratio is in `[0, 1]`. Replay sampling already randomizes the
batch, so reanalyze the first `floor(B * ratio)` samples, matching the
EfficientZero worker's `indices[:re_num]` behavior.

## Implementation

1. Extend the target/reanalysis snapshot to include representation, dynamics,
   and prediction networks. Create it when value or policy reanalysis is
   enabled; freeze it and hard-copy all online state at `target_update_interval`.
2. Reuse `AtariAgent`/`BatchedNetworkEvaluator` and `MCTS.search_batch` with the
   target networks. Run under inference mode and configured learner precision.
3. For selected samples, run MCTS at every valid replay state from root through
   the unroll horizon. Use real stacked replay observations as roots, configured
   Dirichlet root noise, and latent dynamics expansion only. The asynchronous
   pipeline may reuse a result for the same stable transition ID and target
   weight version; clear this cache whenever target weights change.
4. Replace `ReplayBatch.policy_targets` only where both the sample-selection
   mask and `target_mask` are true. Normalize fresh root visit counts.
5. Keep stored policies for the other 1%, padded/terminal positions, and when
   the ratio is zero. Never rewrite replay contents, actions, or rewards.
6. Batch roots across samples/offsets to avoid one search call per state. Record
   policy reanalysis separately in learner profiling.
7. Save the complete target/reanalysis network in checkpoints. Value-only
   reanalysis must still work when policy reanalysis is disabled.

## Tests

- A ratio of `0.99` reanalyzes `floor(0.99 * B)` samples; `0` preserves all
  stored policies.
- Only selected valid targets change, and visit distributions sum to one.
- Search uses delayed target weights, including target dynamics, not online
  weights.
- Replay remains immutable, target synchronization includes all networks, and
  checkpoint/config round trips preserve the feature.
