# Self-Play Lookahead and Prepared Replay Refactor

## Goal

Store each normal self-play block as 400 sampleable transitions plus enough overlapping lookahead transitions to build every replay target locally. Then prepare all replay arrays and fixed-horizon targets once when the trajectory is added, instead of recalculating them for every sampled batch.

The replay horizon is fixed for the lifetime of a buffer:

```python
FIFOReplayBuffer(
    max_transitions,
    unroll_steps=5,
    td_steps=5,
    discount=0.997,
    ...,
)
```

Consequently, `sample()` should not receive `unroll_steps`, `td_steps`, or `discount`. This makes target preparation an insertion-time operation rather than a parameter-dependent sampling operation.

This decision supersedes the lazy `(td_steps, discount)` cache proposed in `plans/18.replay_fill_cache_optimization.md`.

## Self-play trajectory behavior

For the production configuration:

- `trajectory_length = 400`
- `lookahead_steps = max(unroll_steps, td_steps) = 5`
- a complete nonterminal stored block contains 405 transitions
- only the first 400 transitions are replay starts
- the final 5 transitions provide local unroll and bootstrap context
- those same 5 transitions are also the first 5 transitions of the next block

When an active builder reaches 400 transitions:

1. Freeze its sampleable length at 400.
2. Start the next block at the same logical boundary.
3. Continue collecting 5 transitions.
4. Append each transition both as lookahead for the frozen block and as ordinary data for the next block.
5. Finalize the frozen block after it has 5 lookahead transitions.

If the environment terminates or truncates while lookahead is being collected, finalize the frozen block with the available terminal context. Terminal blocks do not require a bootstrap beyond the episode boundary.

Flushing an unfinished worker may emit a block with no complete lookahead. Replay must preserve the existing masking behavior for unavailable nonterminal targets.

## Data model

Keep `GameTrajectory` as the immutable output of self-play, including:

- compact frames: initial stack plus one frame per stored transition
- actions and rewards
- search results
- terminal/truncation flags
- `lookahead_steps`
- `len(trajectory)` returning only sampleable transitions
- `stored_transition_count` including lookahead

Do not add mutable replay caches to `GameTrajectory`. Replay should convert it into a private `_StoredTrajectory` during `FIFOReplayBuffer.add()`.

### `_StoredTrajectory`

Store only replay-required metadata and contiguous NumPy arrays:

- trajectory identity
- stack size
- sampleable and stored transition counts
- terminal/truncation and lookahead metadata
- `frames: uint8`
- `actions: int64`
- `rewards: float32`
- normalized `policy_targets: float32`
- `root_values: float32`
- precomputed `value_targets: float32`
- precomputed `value_valid_mask: bool`

Do not retain the source `GameTrajectory` in the replay wrapper. Otherwise contiguous frame preparation would keep both representations alive and approximately double frame storage.

## Replay API change

Move the fixed target configuration from `sample()` to construction:

```python
replay = FIFOReplayBuffer(
    max_transitions=config.replay.max_transitions,
    unroll_steps=config.training.unroll_steps,
    td_steps=config.training.td_steps,
    discount=effective_discount,
    seed=config.seed,
    priority_alpha=config.replay.priority_alpha,
)

batch = replay.sample(
    batch_size,
    priority_beta=priority_beta,
    include_value_bootstraps=use_reanalysis,
)
```

Constructor validation should match the current sample validation:

- horizons are positive integers
- discount is finite and in `[0, 1]`
- booleans are rejected as integers

The values become read-only replay properties and determine all batch shapes. Remove them from `_fill_batch_arrays()` and other helpers where they can be read from replay state.

Update all call sites and tests rather than retaining per-call overrides. A replay buffer must not mix target definitions over its lifetime.

## Insertion-time preparation

`FIFOReplayBuffer.add()` should perform all trajectory-dependent calculations before mutating FIFO state:

1. Validate identity, action-space size, stack size, frame shape, and transition lengths.
2. Call `trajectory.validate_lookahead(self.unroll_steps, self.td_steps)` once.
3. Convert frames, actions, rewards, visit counts, and root values to contiguous arrays.
4. Validate positive visit-count totals and normalize policy targets once.
5. Build the full fixed-horizon value-target table using the replay's `td_steps` and `discount`.
6. Only after preparation succeeds, evict old trajectories and append `_StoredTrajectory`.

Because horizons are fixed, remove the replay-wide `_validate_lookahead()` scan from every `sample()` call.

### Precomputed value table

Build values for every stored state position, including the state at `stored_transition_count`:

- compute discount powers once in replay initialization
- compute the bootstrap discount once in replay initialization
- accumulate reward returns in float64
- add the stored root value when a fixed-horizon bootstrap exists
- cast final targets to float32
- precompute the validity mask with exact current terminal and incomplete-tail semantics

`unroll_steps` does not require a separate table. Sampling a start copies a contiguous `unroll_steps + 1` slice from the trajectory-wide value and validity arrays.

Bootstrap values and observations can be copied directly from prepared root-value and frame slices because `td_steps` is fixed.

## Faster batch filling

After insertion-time preparation, `_fill_batch_arrays()` should only:

1. Resolve sampled flat indices to stored trajectories and local starts.
2. Copy contiguous frame, action, reward, policy, and value slices.
3. Set masks and clear only unavailable terminal/incomplete tails.
4. Copy bootstrap frame and root-value slices when requested.
5. Copy transition IDs and importance weights.

The hot path must not:

- normalize visit counts
- extract root values from `SearchResult` objects
- convert trajectory tuples repeatedly
- construct discount vectors
- call `np.pad()` or `sliding_window_view()` per sampled row
- recalculate n-step values

Ordinary complete nonterminal blocks should fully overwrite their batch rows without blanket-clearing all small target arrays. Masked bootstrap-frame regions must remain deterministic zeros.

## Benchmark baseline

Production-shape synthetic benchmark on the current working tree:

- replay starts: 10,000
- trajectories: 25 × 400 sampleable transitions
- lookahead: 5
- batch: 256
- RGB `96x96`, stack 4
- unroll/TD: 5/5
- actions: 18

| Operation | Mean |
|---|---:|
| `_fill_batch_arrays()`, bootstrap enabled | 24.2 ms |
| Full `sample()`, bootstrap enabled | 30.7 ms |
| `_fill_batch_arrays()`, bootstrap disabled | 14.6 ms |
| Full `sample()`, bootstrap disabled | 18.0 ms |

A prototype with prepared trajectory arrays and precomputed values reduced isolated bootstrap-enabled fill time to 11.5 ms, approximately 2.1× faster.

Add `scripts/benchmark_replay.py` before implementation and report:

- trajectory preparation/add time
- cold and warm sample times
- fill time using fixed sampled locations
- bootstrap enabled and disabled
- mean, median, and p95
- replay memory/RSS where reliable

Insertion cost must be reported, but it should be strongly amortized: production performs hundreds of learner samples per collection iteration while adding only a few trajectories.

## Implementation order

1. Add the permanent benchmark and save a baseline JSON result.
2. Move `unroll_steps`, `td_steps`, and `discount` into `FIFOReplayBuffer.__init__()`.
3. Update training and test call sites to use the new API.
4. Validate lookahead on insertion instead of every sample.
5. Add `_StoredTrajectory` and contiguous invariant arrays.
6. Precompute policy and value targets during `add()`.
7. Rewrite `_fill_batch_arrays()` as direct slice copies.
8. Remove unnecessary whole-array clearing.
9. Profile again before considering grouped/advanced-index gathering.

## Tests

### Self-play

- a nonterminal 400-transition block waits for 5 additional transitions
- the completed block reports length 400 and stored count 405
- all 5 lookahead transitions also appear at the start of the next block
- terminal and truncated boundaries finalize correctly during lookahead collection
- multiple consecutive block boundaries preserve identity and overlap
- flushing incomplete builders preserves masking semantics

### Replay configuration

- constructor rejects invalid horizons and discounts
- sample no longer accepts horizon or discount overrides
- output shapes use constructor `unroll_steps`
- lookahead is rejected by `add()` when insufficient for fixed replay horizons
- a failed preparation does not evict or otherwise mutate existing replay state

### Target equivalence

Compare optimized arrays against a small reference implementation for:

- terminal, truncated, complete-lookahead, and incomplete trajectories
- starts near both sampleable and stored tails
- stack sizes 1 and 4
- several constructor horizon combinations
- discounts `0.0`, a normal fractional value, and `1.0`
- bootstrap metadata enabled and disabled

Use exact comparisons for frames, actions, masks, and IDs, and tight float32 tolerances for policy/value targets.

Run:

```bash
uv run pytest tests/test_selfplay.py tests/test_replay.py -q
uv run pytest -q
```

## Acceptance criteria

- every sampleable transition has sufficient local context or is correctly masked
- replay never needs to locate a next trajectory for target construction
- all fixed-horizon values and policies are prepared once during insertion
- warm bootstrap-enabled fill time decreases by at least 35%, targeting 12–14 ms
- warm end-to-end sample time decreases by at least 25%
- no steady-state duplicate frame payload is retained
- prioritized sampling, stable IDs, FIFO eviction, and importance weights are unchanged
- full tests pass

## Implementation result

Implemented with `scripts/benchmark_replay.py` as the reproducible benchmark. On the production-shape benchmark described above:

| Operation | Before | After | Reduction |
|---|---:|---:|---:|
| `_fill_batch_arrays()`, bootstrap enabled | 24.2 ms | 8.56 ms | 64.6% |
| Full `sample()`, bootstrap enabled | 30.7 ms | 15.61 ms | 49.2% |
| `_fill_batch_arrays()`, bootstrap disabled | 14.6 ms | 4.42 ms | 69.7% |
| Full `sample()`, bootstrap disabled | 18.0 ms | 7.67 ms | 57.4% |

Trajectory preparation averaged 2.37 ms per 400+5-step block. Prepared replay array storage for 10,000 RGB `96x96` starts was approximately 283.8 MB. The full test suite passes with 109 tests.
