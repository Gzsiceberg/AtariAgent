# C++ Reanalysis Worker

## Goal

Replace the Ray-based `ReanalysisWorker` with an in-process C++ reanalysis engine running on a dedicated thread.

## Targets

- Remove the Ray actor and actor-specific reanalysis lifecycle.
- Run reanalysis asynchronously on a dedicated C++ worker thread.
- Pass reanalysis requests and results between Python and C++ without copying tensor storage.
- Move request validation, ordering, queueing, and result matching into C++.
- Move target-network ownership, inference, weight synchronization, and weight-version handling into C++.
- Move reanalyzed-target caching, cache lookup, cache population, and cache invalidation into C++.
- Preserve bounded backpressure, timeout behavior, and stale-result detection.
- Preserve current value-target and policy-MCTS reanalysis behavior.
- Preserve deterministic behavior for equivalent seeds and configurations.
- Remove Ray from the reanalysis path and remove it as a dependency if it is no longer used elsewhere.
- Maintain compatibility with the existing learner, replay batch, checkpoint, and configuration interfaces where practical.
- Validate numerical correctness, thread safety, memory ownership, and clean shutdown.
- Benchmark request latency, training throughput, CPU usage, GPU utilization, and peak memory against the Ray implementation.
