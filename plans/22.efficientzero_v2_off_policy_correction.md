# EfficientZero V2 Off-Policy Correction

## Goal

Add EfficientZero V2's mixed value target to the current Atari training code.

## Behavior

For each sampled replay state, prepare two value targets:

1. **TD target** using five stored rewards and a fresh delayed-network
   bootstrap:

   \[
   z_t^{TD}=\sum_{j=0}^{4}\gamma^j r_{t+j}+\gamma^5v(s_{t+5}).
   \]

2. **Search value** returned by the MCTS already used for policy reanalysis.
   This is the tree's root value, so no additional search is needed.

Select the training target as follows:

| Condition | Target |
|---|---|
| Learner step is below `30,000` | TD target |
| Sample is among the newest `5,000` replay transitions | TD target |
| Otherwise | MCTS search value |

The same selection is applied to all value targets in a sampled unroll. Invalid
or padded search positions continue using their masked TD target.

This differs from EfficientZero V1: V2 does not shorten `td_steps` as replay
data gets older. It replaces the TD target for stale data with the current
search value.

## What is missing in this repository

The current code already:

- builds fixed five-step TD targets;
- refreshes the bootstrap with the delayed target network;
- runs MCTS for policy reanalysis;
- assigns permanent replay transition IDs.

It does not yet use the MCTS root values. Those values are returned by search
but discarded, and replay batches do not identify whether a sample is recent
or stale.

## What to implement

1. Keep the root value returned by each policy-reanalysis MCTS search.
2. Add each sampled transition's age, or an equivalent recent/stale mask, to
   `ReplayBatch`. Use permanent transition IDs so FIFO eviction does not reset
   age.
3. Add the mixed-target selection described above after reanalysis and before
   training.
4. Use the selected mixed value for both value loss and replay-priority error.
5. Extend the native reanalysis cache to retain the TD value, MCTS root value,
   and policy for each target-network version.
6. Keep replay contents immutable and reuse the existing MCTS call.
7. Add tests for the `30,000`-step switch, the `5,000`-transition freshness
   boundary, FIFO eviction, cache hits, padded states, and priority updates.

## Default parameters

Use the official EfficientZero V2 Atari defaults:

```yaml
training:
  value_target: mixed
  mixed_value_start_step: 30000
  mixed_value_threshold: 5000
  target_update_interval: 1000
```
