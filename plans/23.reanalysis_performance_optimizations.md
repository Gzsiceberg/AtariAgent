# Reanalysis Performance Optimizations

## Goal

Reduce replay sampling, target reanalysis, MCTS, memory-transfer, and target-publication overhead without changing EfficientZero V2 training semantics.

## Plan

1. **Replace prioritized replay's full-buffer scan**
   - Replace per-batch probability construction and `np.random.choice` with a sum tree or Fenwick tree.
   - Support priority updates and weighted unique sampling in `O(log N)` per item.
   - Preserve stable transition IDs, FIFO eviction, and original importance weights.

2. **Parallelize native reanalysis tree work**
   - Add bounded OpenMP parallelism to independent root traversal, expansion/back-up, and result extraction in `cpp/inference/mcts.cpp`.
   - Keep Torch/CUDA operations outside OpenMP regions and honor `reanalysis_worker_num_threads`.

3. **Remove MCTS heap-allocation hot spots**
   - Store children as contiguous index ranges instead of per-node vectors.
   - Replace tie-candidate vectors with reservoir sampling.
   - Pass policy logits by span and reuse path/min-max scratch storage.
   - Replace repeated full-tree min/max rebuilding with an exact incremental structure if profiling confirms it is beneficial.

4. **Consolidate replay frame buffers**
   - Store one `stack_size + unroll_steps + td_steps` frame tensor.
   - Provide policy and TD-bootstrap windows as views.
   - Transfer only the learner's shorter frame window after reanalysis.
   - Preserve terminal padding and pinned-memory behavior.

5. **Avoid MCTS result CPU–GPU round trips**
   - Keep visit counts and root values on CPU after native MCTS.
   - Assemble reanalyzed CPU policy and search-value targets directly in the engine.
   - Keep only model inputs, latent states, and recurrent inference on GPU.

6. **Use contiguous reanalysis-cache storage**
   - Replace per-entry policy vectors with contiguous value, search-value, and policy arrays plus a `state_id -> slot` lookup.
   - Reserve expected capacity per target version.
   - Apply hits and duplicates through direct contiguous writes instead of temporary vectors, `from_blob().clone()`, and repeated `index_put_()` calls.

7. **Remove redundant native output clones**
   - Allocate final output tensors outside `InferenceMode` and mutate them during processing.
   - Remove the final value, search-value, and policy clones where PyTorch tensor-lifetime rules permit.

8. **Publish target weights device-to-device**
   - Replace the online-GPU → CPU → target-GPU snapshot path with immutable GPU snapshots and device-to-device copies.
   - Use CUDA events or stream ordering so learner updates cannot race target synchronization.
   - Preserve ordered publication and cache invalidation at each target version.

## Validation

For each optimization:

- compare values, policies, priorities, masks, and cache behavior against the current implementation;
- test duplicate samples, FIFO eviction, terminal padding, and target-version changes;
- measure learner throughput, reanalysis latency, cache hit cost, CPU utilization, H2D/D2H bytes, and peak pinned/GPU memory;
- land changes independently, starting with prioritized replay, MCTS allocation/parallelism, and frame consolidation.
