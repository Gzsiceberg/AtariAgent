# Reanalysis Performance Optimizations

## Goal

Reduce replay sampling, target reanalysis, MCTS, memory-transfer, and target-publication overhead without changing EfficientZero V2 training semantics.

## Implementation strategy

Land and benchmark independent waves. The first wave prioritizes the measured reanalysis and frame-transfer bottlenecks. Lower-impact replay-tree, cache-layout, and target-publication changes remain deferred until production profiling justifies their complexity.

## Plan and status

1. **Replace prioritized replay's full-buffer scan — profiled; remains deferred**
   - Replace per-batch probability construction and `np.random.choice` with a sum tree or Fenwick tree.
   - Support weighted unique sampling by temporarily removing selected leaves and restoring them in `O(batch_size log N)`.
   - Compute importance weights from the original normalized probabilities, not conditional draw probabilities.
   - Preserve stable transition IDs and trajectory-level FIFO eviction.
   - Replace priority-array slicing, concatenation, and maximum scans as part of the same ring-buffer design.
   - Revisit only if sampling becomes material at larger replay sizes. After the first wave, `_sample_context()` is 1.24 ms out of a 17.56 ms complete sample (7.1%), so a tree and ring-buffer rewrite is not currently justified.

2. **Parallelize native reanalysis tree work — implemented**
   - Enable OpenMP for the production `_models_native` extension, not only `_mcts_native`.
   - Parallelize independent root traversal, expansion/back-up, and result extraction in `cpp/inference/mcts.cpp`.
   - Keep Torch/CUDA operations outside OpenMP regions.
   - Store the configured thread count in the production MCTS module so `reanalysis_worker_num_threads` is honored by the C++ worker thread rather than relying on OpenMP thread-local defaults.

3. **Remove MCTS heap-allocation hot spots — partially implemented**
   - Store children as contiguous index ranges instead of per-node vectors. **Done.**
   - Replace tie-candidate vectors with reservoir sampling. **Done.**
   - Pass policy logits by span and write visit counts directly into final output storage. **Done.**
   - Reserve path/min-max scratch storage and reuse CPU/device traversal staging tensors across simulations. **Done.**
   - Reuse recurrent-output concatenation storage. **Profiled; not planned.** All `aten::cat` calls together account for 2.39 ms of CUDA time per 254.96 ms production-shaped direct policy request (0.94%); the recurrent-output concatenation is only a subset of that upper bound.
   - Replace repeated full-tree min/max rebuilding with an exact incremental multiset/indexed structure. **Profiled; not planned at 50 simulations.** Pure native tree traversal plus expansion/back-up/rebuild totals about 10.15 ms for one 768-root chunk, while all tree work is still only an estimated 8% upper bound for the two-chunk 254.96 ms policy request. Revisit for materially higher simulation counts or CPU-only inference.

4. **Consolidate replay frame buffers — implemented**
   - Store one `stack_size + unroll_steps + td_steps` frame tensor for reanalysis batches.
   - Provide policy and TD-bootstrap windows as views over the shared tensor.
   - Transfer the combined frame tensor to the reanalysis device once and reconstruct both device windows as views.
   - Drop reanalysis metadata before learner transfer so only the shorter learner frame window is copied.
   - Preserve policy terminal padding, bootstrap masks, shared pinned-memory storage, and compatibility with synthetic batches that still provide separate frame tensors.
   - Count shared tensor storage once in pending-payload metrics.

5. **Avoid MCTS result CPU–GPU round trips — implemented for the native engine**
   - Keep normalized visit policies and root values on CPU after native MCTS.
   - Return compact `(positions, policies, root_values)` outputs from target search.
   - Assemble CPU policy and search-value targets directly in the reanalysis engine.
   - Avoid policy-target/search-target H2D copies and full policy/search-result D2H copies in the asynchronous engine.
   - Retain the existing public `reanalyze_policies()` behavior for direct callers and tests.

6. **Use contiguous reanalysis-cache storage — profiled; not planned**
   - Replace per-entry policy vectors with contiguous value, search-value, and policy arrays plus a `state_id -> slot` lookup.
   - Reserve expected capacity per target version.
   - Apply hits and duplicates through direct contiguous writes instead of temporary vectors, `from_blob().clone()`, and repeated `index_put_()` calls.
   - A production-shaped 200-update, 10,000-transition run searched only 10,000 of 307,200 requested roots (30.72x reduction). The 153 fully cached requests had a 0.343 ms median and 0.393 ms p95 worker time. Partial requests were dominated by target inference/MCTS chunk cost rather than cache lookup, so a cache-layout rewrite has no meaningful current payoff.

7. **Remove redundant native output clones — implemented**
   - Create cache/output tensors outside a function-wide `InferenceMode` scope.
   - Mutate normal CPU output tensors with reanalyzed values, policies, and search values.
   - Remove the final value, search-value, and policy clones previously needed to convert inference tensors.

8. **Publish target weights device-to-device — profiled; not planned**
   - Separate publication state from the CPU target snapshot retained for checkpoints.
   - Evaluate direct GPU source references versus immutable GPU clones; publication is synchronous and the online model cannot be updated until it completes.
   - Use CUDA events or stream ordering so learner updates cannot race target synchronization.
   - Preserve ordered publication and cache invalidation at each target version.
   - An 11.35 MB production target snapshot measured 3.32 ms GPU-to-CPU plus 2.36 ms CPU-to-target-GPU, or 5.68 ms total. At one publication per 200 updates this amortizes to 0.028 ms/update, so the additional snapshot-lifetime and CUDA-ordering complexity is not justified.

## First-wave measurements

Measured locally on an NVIDIA GeForce RTX 4070 Ti with production-shaped batch 256, unroll/TD 5, 50 simulations, action size 18, BF16, and chunk size 768.

### Replay at 100,000 transitions

| Metric | Before | First wave | Change |
|---|---:|---:|---:|
| Complete bootstrap-enabled sample | 24.01 ms | 17.56 ms | -26.9% |
| Fixed-location bootstrap-enabled fill | 11.68 ms | 9.02 ms | -22.8% |
| Sampling context | 1.71 ms | 1.24 ms | -27.4% |

The complete result includes reduced frame allocation/copying; the priority sampler itself is unchanged.

### Cold native reanalysis

| Metric | Before | First wave |
|---|---:|---:|
| Mean worker duration, four threads | 593.82 ms | 365.57 ms |
| Requests/s | 1.68 | 2.73 |
| Pending payload per batch | 127,555,328 bytes | 99,243,776 bytes |

On the final first-wave build over eight measured requests, one OpenMP thread measured 544.06 ms and four threads measured 365.57 ms, a 32.8% worker-time reduction from bounded root parallelism. The remaining gain comes from tree allocation/staging changes, shared frame transfer, CPU result assembly, and clone removal.

## Deferred-work decision profiling

Measured on an NVIDIA GeForce RTX 3060 Ti with batch 256, unroll/TD 5, 50 simulations, action size 18, BF16, chunk size 768, and four MCTS threads.

### Realistic cache evolution

A 200-update run sampled from a 10,000-transition replay and included learner updates.

| Metric | Result |
|---|---:|
| Updates/s | 14.26 |
| Mean reanalysis worker time | 27.94 ms |
| Requested policy roots | 307,200 |
| Searched policy roots | 10,000 |
| Search reduction | 30.72x |
| Fully cached request median | 0.343 ms |
| Fully cached request p95 | 0.393 ms |

Requests with any remaining misses stayed dominated by the fixed target-inference/MCTS chunk cost: the 90–99% and 99–100% effective-hit buckets both had approximately 84–86 ms median worker time. Contiguous cache storage could only optimize the already sub-millisecond fully cached path and is therefore closed as not planned.

### Native MCTS hot spots

A direct production-shaped native policy request measured 254.96 ms mean wall time. Across the complete request, all `aten::cat` operations—not only recurrent-output assembly—used 2.39 ms CUDA time and 1.70 ms CPU self time per request. Reusing concatenation storage has a sub-1% CUDA upper bound.

A focused native-tree benchmark over 768 roots showed expansion/back-up/rebuild increasing from 0.074 ms per simulation over the first ten simulations to 0.259 ms over the last ten, confirming growth from full min/max rebuilding. Even so, traversal plus all expansion/back-up/rebuild work totaled only 10.15 ms per 50-simulation chunk. For the two production chunks, all native tree work is an estimated 20.3 ms (8% of request wall time), and min/max rebuilding is only part of that total. An incremental exact structure is not justified at the current simulation count.

### Target publication

| Stage | Mean | Median | p95 |
|---|---:|---:|---:|
| Online GPU to 11.35 MB CPU snapshot | 3.32 ms | 2.89 ms | 4.37 ms |
| CPU snapshot to target GPU | 2.36 ms | 2.35 ms | 2.62 ms |
| Combined | 5.68 ms | — | — |

At the configured 200-update publication interval, the combined path contributes roughly 0.028 ms/update. Device-to-device publication remains unnecessary unless model size or publication frequency changes substantially.

## Remaining work

No deferred optimization is currently justified by the measurements. Keep the benchmark coverage and reopen work only when production profiles cross one of these triggers:

- replay sampling becomes a material share of complete sample or learner time;
- simulation counts increase enough for native tree rebuilding to become material;
- partial-cache CPU preparation becomes visible after separating it from inference/MCTS chunk time;
- target publication frequency or model size increases enough for publication to affect throughput.

## Validation

For each optimization:

- compare values, policies, priorities, masks, and cache behavior against the current implementation;
- test duplicate samples, FIFO eviction, terminal padding, shared pinned storage, separate-frame compatibility, and target-version changes;
- measure learner throughput, reanalysis latency, cache hit cost, CPU utilization, H2D/D2H bytes, and peak pinned/GPU memory;
- land changes independently and retain benchmark scripts for regression testing.

The first wave adds coverage for consolidated shared frame storage and native-engine consumption. Run:
